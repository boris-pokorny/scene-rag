# Published contracts of `extraction`

Contracts other services consume, released to the schema registry:

| Contract | Consumers | Published by | File |
|---|---|---|---|
| scene record | `retrieval` (chunking) | scene-api | `scene-record.schema.json` |
| scene set summary, asset version, page, error | `retrieval` | scene-api | `scene-set-summary.schema.json`, `asset-version.schema.json`, `page.schema.json`, `error.schema.json` |
| `scene-api` API (OpenAPI 3.1) | `retrieval` | scene-api | `scene-api.openapi.json`, generated by `pdm run openapi` from the application with the schemas above embedded under `components` |
| `AssetVersioned`, `AssetRetired` events | `retrieval` | ingestion (outbox) | not yet |
| `ScenesPublished` event | `retrieval` | enrichment | not yet |

`samples/` holds one valid document per schema, consistent with `../internal/samples/`. The
contract tests under `tests/contract/` check every schema, every sample, the encoder's output
and the OpenAPI document against each other; `tests/contract/test_scene_api_openapi.py` also
fails when the committed OpenAPI document differs from the generated one. The Asset Registry is
an internal store; its record schema lives in `../internal/`.
