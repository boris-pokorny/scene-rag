# Published contracts of `retrieval`

Contracts other services consume, released to the schema registry:

| Contract | Consumers | Published by | File |
|---|---|---|---|
| query API over HTTP (OpenAPI 3.1) | `evaluation`, UIs, services | query-api | `query-api.openapi.json`, generated from `*.schema.json` by `pdm run openapi` |
| query API over MCP (tools, resource templates, their schemas) | LLM clients, IDEs, agents | query-api | `query-api.mcp.json`, generated by `pdm run mcp-schemas` |

The Chunk Store and the Search Index are internal stores; their record schemas live in
`../internal/`. What this service consumes (the scene record, the scene set summary, the
asset version and the `scene-api` API) is published by `extraction`; the chunking step keeps
its own decoder of those documents in `src/scene_rag/retrieval/chunking/scene_api_client.py`,
pinned by the samples under `tests/contract/samples/`; the query-api role keeps its own in
`src/scene_rag/retrieval/query_api/scene_api_client.py`.

The request and response bodies of the HTTP API are the hand-written `*.schema.json` files
here, with one sample each under `samples/`; the MCP tools return the same response
documents as structured output. Every non-2xx answer has the shape of `error.schema.json`.
